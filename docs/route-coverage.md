# حفظ ظاهر تأییدشده و تکمیل مسیرهای پروژهٔ اصلی

کاربر تأیید کرد که نسخهٔ سالم با طرح نهایی از پوشهٔ cloneشدهٔ `arvand-git` و سایت پورت 8135 اجرا می‌شود. این نسخه مبنای ظاهر صفحهٔ نخست باقی مانده است؛ فایل‌های قالب، تنظیمات اتصال، DLLها، احراز هویت و مسیریابی آن در این تغییر عوض نشده‌اند.

در مقایسه با سایت Intranet، تعریف مسیرها در IntranetAdmin موجود بود اما فایل مقصد ۱۷ صفحهٔ عمومی وجود نداشت. خود صفحه‌ها و کدهای اصلی آن‌ها، به‌همراه helper تاریخ و انتخاب‌گر تماسِ مفقود، منتقل شدند. صفحه‌های داخلی از منطق و masterهای اصلی‌شان استفاده می‌کنند؛ این تغییر به معنی بازطراحی همهٔ صفحه‌های داخلی نیست.

| قابلیت | صفحهٔ واقعی منتقل‌شده |
| --- | --- |
| معرفی و تماس | About، ContactUs، ExecutiveManagers |
| خبر | NewsArchive، ShowNews |
| اطلاعیه | ShowAnnouncements |
| صفحات محتوایی | ShowPage، Text |
| جستجوی اصلی | Search |
| چاپ و Word | Print، PrintWord |
| RSS | RSS |
| نظرسنجی | ShowPoll |
| درخواست تعاونی | RegisterHouseCooperative، EditHouseCooperative |
| انتخاب تماس و تصویر امنیتی | SelContact، SecImage |

همچنین `SystemMng/PageAction/SelContact` و `App_Code/CLSShamsiDate.vb` از پروژهٔ اصلی اضافه شدند. نسخهٔ منتقل‌شدهٔ RSS، import صریح `System.Xml.Linq` دارد. جستجوی منتقل‌شده، نتایج صفحه‌ها را به واحد جاری محدود می‌کند و اسناد را مطابق همان مجوزهای فهرست فایل‌های صفحهٔ نخست نشان می‌دهد؛ عنوان اسناد خصوصی بدون مجوز در نتایج قرار نمی‌گیرد.

چون صفحه‌های مستقل اکنون وجود دارند، کنترل قالب خودکار پیوندهای اصلی را تولید می‌کند. جستجو به `Search?q=...`، خبر به `ShowNews/{id}` و اطلاعیه به `ShowAnnouncements/{id}` می‌رود؛ دیگر برای این مسیرها نیازی به حالت جایگزین داخل پنجره نیست.

در Visual Studio همان **IntranetAdmin** را Startup Project بگذارید و سایت قبلی پورت 8135 را اجرا کنید. تنظیمات دیتابیس سالم را تغییر ندهید. برای خبر، اطلاعیه، نظرسنجی، چاپ و صفحات محتوایی، شناسهٔ معتبر از داده‌های خود سامانه لازم است.

## شواهد بررسی

- اسکریپت `python tools/check_route_coverage.py` حضور هر ۱۹ ثبت مسیر (شامل Web API)، هر ۷۸ فایل ASPX پروژهٔ اصلی، هر ۲۱ صفحهٔ ریشه و handler اصلی را تأیید می‌کند. CodeFileها و کنترل‌های ثبت‌شدهٔ صفحه‌های ریشه نیز وجود دارند.
- کد مشترک سایت جداگانه کامپایل شد؛ سپس ۶۵ فایل کد صفحه/کنترل/master با DLLهای واقعی سایت سالم و reference assemblyهای Framework 4.8 کامپایل شدند. برای این بررسی فقط اعلان فیلدهایی که ASP.NET از markup تولید می‌کند، در یک harness خارجی ساخته شد. این بررسی جای parser و اجرای IIS را نمی‌گیرد.
- فایل‌های موجودِ سایت سالم، از جمله Web.config، Global.asax، default.aspx و دارایی‌های طرح، با نسخهٔ قبلی بایت‌به‌بایت مقایسه و بدون تغییر تأیید شدند.
- آزمون وجود و تطابق مسیرها، معادل پاسخ موفق زندهٔ همهٔ URLها نیست. اجرای عملی همهٔ صفحات، ارسال فرم‌ها و کنترل مجوزها با دیتابیس کاربر در این محیط لینوکسی ممکن نیست و باید در IIS با داده‌ها و حساب‌های واقعی توسعه بررسی شود.
