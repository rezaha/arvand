# نصب قالب روی همان سایت سالم پورت 8135

آدرس اعلام‌شدهٔ کاربر `http://localhost:8135/fa-IR/AR/default` است. در Solution، این پورت به سایت **IntranetAdmin** اشاره دارد؛ سایت **Intranet** روی پورت 4140 تنظیم شده است. این دو سایت تنظیمات اتصال متفاوت دارند. خطای ورود SQL سایت 4140 را نباید به کارکرد سایت 8135 نسبت داد.

قالب به صفحهٔ نخست خود `IntranetAdmin` متصل شده است. توضیح این سند دربارهٔ مرحلهٔ نصب قالب است؛ [تکمیل بعدی قابلیت‌های مدیریت، دانلود و XLSX](feature-integration.md) تغییرات عملکردی بعدی را توضیح می‌دهد. `Web.config`، `Global.asax`، `SiteHelper`، `BasePage`، `BaseUserControl`، DLLها و handler دانلود این سایت تغییر نکرده‌اند. اتصال و احراز هویت همان سایت سالم استفاده می‌شود؛ هیچ اتصال یا رمزی از سایت 4140 به آن منتقل نشده است.

## دریافت و اجرا

۱. اجرای سایت را متوقف کنید و در پوشهٔ cloneشده اجرا کنید:

```powershell
git pull --ff-only origin main
.\Open-Arvand.cmd
```

۲. در Visual Studio روی **IntranetAdmin** راست‌کلیک و **Set as StartUp Project** را انتخاب کنید.

۳. Ctrl+F5 بزنید و همان آدرس قبلی را باز کنید:

```text
http://localhost:8135/fa-IR/AR/default
```

اگر سایت سالم شما در پوشهٔ دیگری با تنظیمات محلی اجرا می‌شود، ابتدا تغییرات را در همان checkout بررسی کنید. Web.config یا پایگاه دادهٔ سالم را با تنظیمات سایت دیگر جایگزین نکنید. اگر pull به تغییرات محلی اعتراض کرد، آن‌ها را reset نکنید.

## سازگاری قالب با سایت سالم

- مسیر `default` به پوسته و کنترل جدید متصل شده است؛ لایه‌های داده و مدل احراز هویت قبلی باقی هستند.
- صفحهٔ نخست دیگر چیدمان قدیمی وب‌پارت‌های Container را رندر نمی‌کند؛ دادهٔ پنل‌ها از سرویس‌های همان سایت و همان واحد گرفته می‌شود.
- صفحه‌های عمومیِ موجود در پروژهٔ اصلی به این سایت نیز منتقل شده‌اند: جستجو، معرفی، تماس، خبر، اطلاعیه، چاپ، RSS، نظرسنجی و درخواست تعاونی. قالب به‌صورت خودکار وجود فایل واقعی را تشخیص می‌دهد و از مسیر همان صفحه استفاده می‌کند. [گزارش پوشش مسیرها](route-coverage.md)
- نمایش داخل پنجره و جستجوی محدود داخل صفحه فقط حالت جایگزین برای زمانی است که صفحهٔ مقصد در نسخهٔ نصب‌شده وجود نداشته باشد؛ در نسخهٔ فعلی مسیرهای اصلی فعال‌اند.
- لینک‌های ثبت‌شدهٔ منوها و سامانه‌ها حفظ می‌شوند. پیوندهای قدیمی احتمالی به صفحه‌های ناموجود نیازمند اصلاح تنظیمات خود منو هستند.
- فایل‌ها همچنان پس از بررسی مجوز کاربر به handler دانلود قبلی می‌روند.
- لوگوی واقعی اروند در فایل مستقل `Images/portal/arvand-header.png` قرار دارد؛ تصویر سربرگ قدیمی سایت سالم تغییر نکرده است.

## اعتبارسنجی

- هر ۶۵ فایل App_Code سایت 8135 به همراه کد صفحهٔ نخست و کنترل جدید، با DLLهای خود همین سایت و reference assemblyهای Framework 4.8 در harness خارجی کامپایل شدند.
- عدم تغییر فایل‌های حساس اجرای سایت سالم با مقایسهٔ بایت‌به‌بایت تأیید شد.
- همان markup سایت IntranetAdmin با دادهٔ آزمایشی برای تست مرورگر استفاده شد. چیدمان دسکتاپ، سه عرض واکنش‌گرا، خبرها و جستجوی بدون صفحهٔ مستقل، فوکوس، اسلایدر، دادهٔ خالی و نمایش امن متن بررسی شدند.
- این محیط لینوکسی به IIS ویندوز و SQL Server کاربر دسترسی ندارد؛ اجرای زندهٔ متصل به پایگاه داده در این محیط تأیید نشده است.

برای بازتولید بررسی ظاهری:

```sh
python3 tools/preview_portal.py --site IntranetAdmin --output /tmp/arvand-admin-portal-preview
python3 -m http.server 8767 --bind 127.0.0.1 --directory /tmp/arvand-admin-portal-preview
# در ترمینال دیگر، با Playwright و Chromium نصب‌شده:
PORTAL_PREVIEW_URL=http://127.0.0.1:8767 node tools/check_portal.cjs
```
